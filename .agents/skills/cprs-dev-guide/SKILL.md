# CPRS 开发导航

确认用户要实现、审查还是解释，并保留已有授权与工作区改动。审查保持只读；此技能不扩大测试、构建、Git 或远程操作权限。

## 按任务定位

| 改动 | 先看什么 |
| --- | --- |
| 账号、调度、额度、用量或后台任务 | [架构](../../../docs/architecture.md)相关模块，再跟踪实际调用链和状态归属 |
| 管理端或模型 HTTP 接口 | [API](../../../docs/api.md)相关章节，核对前端调用、解析、业务执行和响应 |
| 页面、弹窗、文案与交互 | 同类页面、已有组件和[主题](../../../docs/theme.md)，确认成功、空、未知及失败状态 |
| 配置、容器、备份、更新 | [部署](../../../deploy/README.md)相应操作；版本与索引另看[发行](../../../docs/releasing.md) |
| 数据库 | [迁移规则](../../../backend/migrations/README.md)，保持已应用迁移字节不变 |
| 开发环境与检查命令 | [开发文档](../../../docs/development.md)，先读拟运行脚本再按授权执行 |

只补读受影响章节，不要求全量通读或加载不存在的外部技能。发现代码时遵守当前会话工具规则，不建立第二套检索要求。

## 实现与收尾

1. 沿现有链路确认事实的拥有者，特别检查 provider 能力门禁、凭据持久化、流式后续更新和失败恢复；避免页面与后端各自解释同一业务事实。
2. 上游字段、权限、费用和权益使用官方合同或真实脱敏观测；样本不足时保留未知，不构造成功响应。Veil 规则展示、密钥和映射存储遵守现有边界。
3. 实现最小改动，补充非显然业务或并发规则的注释；只更新被行为变化影响的文档。
4. 按用户授权选择相关静态检查或验证。使用 pnpm；Rust 检查保留关闭 debug 和 incremental 的配置。记录未验证的集成条件，不自行部署或消费真实权益。
5. 自审最新 diff 的调用点、状态恢复和配置引用，确认必要注释存在；保留无关改动。交付要求见 [CONTRIBUTING.md](../../../CONTRIBUTING.md)。
