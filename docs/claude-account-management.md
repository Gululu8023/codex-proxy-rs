# Claude 账号管理

本文介绍管理端里 Claude 账号能看到哪些信息、这些数据从哪里来，以及和 Codex 账号相比有哪些功能暂不支持。

Claude 账号的数据只有两个来源：Claude Code 同款的 OAuth 接口，以及每次推理请求返回的响应头。上游没给的数据一律显示为"未知"，不会用别的字段推算或补成 0。

## 功能一览

| 功能 | 数据来源 | 说明 |
| --- | --- | --- |
| 基础资料 | 授权或导入时保存 | 名称、邮箱、用户 ID、组织 ID、套餐。Claude 没有 Codex 那样的个人累计统计和头像 |
| 订阅信息 | 打开时实时查询 `/api/oauth/profile` | 订阅开通时间、状态、计费类型 |
| 额度窗口 | 推理请求的响应头 | 5 小时、7 天两个窗口的使用比例和重置时间 |
| 周 / 月额度预测 | 请求记录中的额度观测 | 按已有采样估算本周期能用多少，月度为折算值 |
| 周期用量明细 | CPRS 请求记录 | Token、缓存和按模型拆分的用量，只统计经过 CPRS 的请求 |
| 重置权益 | 实时查询 `/api/oauth/usage` | 只读展示持有的重置卡，不能在 CPRS 中使用 |
| 自动消费重置卡 | — | 不支持，仅 Codex OAuth 账号可用 |

接口字段见 [API：账号个人信息](api.md#账号个人信息)、[订阅信息](api.md#订阅信息)、[周/月额度预测](api.md#周月额度预测)和[主动额度重置卡](api.md#主动额度重置卡)。

## 订阅信息

打开账号的订阅页时，CPRS 用该账号的 OAuth 凭据请求一次官方 profile 接口，并确认返回的用户和组织与账号绑定的一致，避免把别的账号的数据展示到这里。查询不会刷新令牌，也不缓存结果。

上游目前只返回开通时间、订阅状态（如 `active`）和计费类型（如 `stripe_subscription`）。当前账期起止、自动续费、计费周期和币种都不在响应里，界面显示为未知。注意"订阅开通时间"不是"本期开始时间"，也不能用令牌到期时间或额度重置时间代替。

## 额度窗口与预测

Claude 每次推理响应都会带上 5 小时和 7 天窗口的使用比例与重置时间。CPRS 把这两组值连同响应到达时间一起记进请求记录，额度展示、阈值暂停和预测都基于这些观测。

- **只有 5 小时、7 天这两个通用窗口算作账号额度。** 某些模型的专属窗口只展示，不参与账号总量、预测或阈值判断。
- **历史曲线按响应头到达时间排序**，而不是请求完成时间。长时间的流式请求里，额度可能在请求中途就已变化。
- **预测沿用 Codex 账号的采样算法。** 套餐或窗口变化，或者同一窗口的比例突然回落（说明发生了重置），都会重新选取样本。

### 额度阈值自动暂停

给账号设置额度上限后，使用比例达到阈值时账号会自动暂停，不再分配请求。恢复规则：

- 之后观测到完整且低于阈值的额度，自动解除暂停
- 查询失败、缺少窗口或缺少重置时间，**不会**解除已有的暂停
- 新周期开始后，旧周期迟到的较高比例不会让账号再次暂停

## 重置权益（只读）

Claude 部分套餐会发放"额度重置"权益（[官方说明](https://support.claude.com/en/articles/17007452-what-is-a-limit-reset)），可以清空 5 小时或 7 天窗口。CPRS 只读展示库存，不提供使用入口。

查询走管理接口 `GET /api/admin/accounts/reset-credits`，CPRS 再用账号的 OAuth 凭据请求 `GET https://api.anthropic.com/api/oauth/usage?cedar_ember=1`。必须带 `cedar_ember=1`，否则响应里没有库存对象。上游响应示例（已脱敏）：

```json
{
  "eligible": true,
  "grants": [
    {
      "id": "<redacted>",
      "resets_total": 1,
      "resets_left": 1,
      "paused": false,
      "usable_now": true,
      "starts_at": "2026-11-10T21:30:00+00:00",
      "ends_at": "2026-12-10T22:00:00+00:00",
      "clears": ["five_hour", "seven_day", "seven_day_overage_included"]
    }
  ]
}
```

展示规则：

- **可用数量**是有效且未暂停权益的 `resets_left` 之和，不是权益条目数
- `usable_now` 表示此刻能否使用，和"还持有多少张"是两回事
- 过期、未生效、已暂停或已用完的权益照常列出，并标明状态；`clears` 决定这张卡能清空哪些窗口
- 缺少库存、账号不符合资格或响应格式不对时显示查询失败，而不是"0 张"
- 上游可能把 CPRS 的客户端身份判定为不适用（`surface` 不匹配），这时同样显示查询错误

字段对照参考了 CodexBar 的[公开脱敏样本](https://github.com/steipete/CodexBar/issues/3895#issuecomment-5808949886)和[只读实现](https://github.com/steipete/CodexBar/pull/4232)。

## 暂不支持的功能

**在 CPRS 中使用重置卡。** Anthropic 没有公开消费接口的地址、参数、幂等规则和结果确认方式，只读的 OAuth 权限也不代表有消费权限。在这些都核实之前，Claude 账号的 `consumeResetCredit` 能力固定为 `false`，不会向上游发送消费请求，也不会照搬 Codex 的做法。需要使用时，请到 Claude 官方页面手动使用，然后在 CPRS 里刷新额度；新的额度观测会自动解除暂停并更新预测。

**自动消费重置卡。** Claude 账号的 `resetCreditAutomation` 能力固定为 `false`。管理端不显示入口，配置接口和后台任务也会各自检查这个能力，不能靠绕过界面开启。Codex OAuth 账号不受影响。

这些查询都只需要 OAuth 凭据，不需要额外的网页登录态，因此 CPRS 也不提供网页会话导入。
