# 数据库迁移

sqlx 在服务启动、监听请求之前按编号执行迁移，并把文件 checksum 记入 `_sqlx_migrations`。
已应用迁移的字节与记录不一致时，服务会拒绝启动

迁移按递增编号组织，完整清单以本目录 SQL 文件和 `.frozen-sha256` 为准。
业务状态与存储职责见[状态所有权](../../docs/architecture.md#8-状态所有权)，离线恢复见[部署文档](../../deploy/README.md#人工恢复数据库)

## 二开初始化基线

`0001_cprs_initial.sql` 是 CPRS 独立发行线的初始化基线，合并原 `0001`～`0042` 在空库上执行后的最终结构和必要初始数据。
它只支持全新数据库，不兼容源仓库或旧定制版的 `_sqlx_migrations` 历史；切换时须重建数据库，不能通过改写 checksum 或删除迁移记录强行复用旧库。
旧版完整数据库备份同样不能直接恢复给新基线程序使用，应配套旧版程序恢复。

基线保留调用方的 `search_path`，供正常部署及隔离 schema 使用；不包含 SQLx 自己管理的迁移表、数据库所有者、权限或实际业务数据。
初始化时间与互联节点 UUID 在建库时生成，不固定为合并时的值。历史数据回填已折叠为最终默认配置，不再读取旧迁移记录。
后续变更从 `0002` 开始追加。CI 仅允许从旧 `0001_initial.sql` 到此基线的一次发行线切换；基线进入目标分支后恢复完整的只增不改校验。

## 命名约定

- 表名使用小写 `snake_case`，实体集合使用复数，配置与单例状态使用自然语义，如 `runtime_settings`、`request_analytics_build_state`
- 业务归属使用领域前缀，同一实体统一使用 `client_api_key`、`account_group`、`provider` 等术语，不添加 `tbl_` 等对象类型前缀
- 统计时间粒度使用 `15m`、`1h`、`1d`；只保存计数的表保留 `_counts` 后缀
- 表名调整时同步查询、函数体及所属索引和约束名称，已冻结迁移仍保持原样

## 冻结规则

- 同一大版本内，已合入 main 的迁移文件**按字节永久冻结**，包括注释和空白。schema 变更及错误修正都须新增编号迁移，使用 `alter` 或回填补偿；修改原文件会导致已部署实例重启时 checksum 失配，且没有自动恢复路径
- 跨大版本不支持在线升级，目标版本必须使用全新数据目录部署；此时可将已完成升级的 schema 折叠为新的初始化基线
- 支持连续升级的预发行线从首次发布起同样冻结迁移。alpha、beta、rc 到对应正式版必须保留
  已发布迁移的编号与字节；同一轮 exp 的后续发行也只能追加迁移。发布前以该发行线已发布版本
  的数据库验证升级路径，不能只与上一正式版比较。不同 exp 实验线之间、exp 与正式版之间
  不保证迁移历史兼容
- `.frozen-sha256` 使用 `sha256sum` 格式。新增迁移时在同一提交执行 `sha256sum 000N_xxx.sql >> .frozen-sha256` 入册；CI 校验文件字节、SQL 登记完整性及 PR 中清单只增不改

从迁移目录检查已登记文件：

```bash
cd backend/migrations
sha256sum --check --strict .frozen-sha256
```

遇到 checksum 不一致，先核对运行版本和文件来源；不要修改数据库中的 checksum 来绕过校验

## 本地测试库

存储集成测试只连接专用 PostgreSQL 和 Redis，不能复用业务实例。测试从本目录的 CPRS 基线创建独立 schema，验证后清理自己的 schema；备份恢复另建临时数据库。所需环境变量、工具和运行命令见 [后端测试](../../docs/backend-testing.md)。
